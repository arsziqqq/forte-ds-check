# Forte DS Check

Figma-плагин проверяет макет на соответствие дизайн-системе проекта: токены, стили, компоненты.
У каждого проекта и платформы свой **профиль**, и в профиле сколько угодно **источников**: например, «Tokens ИБ», «NEW ИБ Design System» и библиотека иконок.

## Установка

1. Скачайте папку `forte-ds-check` целиком.
2. В Figma Desktop: **Plugins → Development → Import plugin from manifest…** и выберите `manifest.json`.
3. Запуск: **Plugins → Development → Forte DS Check**.

Плагин работает локально. Профили хранятся только на вашем компьютере (`figma.clientStorage`), коллеге их можно передать через «Экспорт профиля».

## Первая настройка (5 минут)

1. Вкладка **Профили → Новый профиль**. Задайте название (например, «ИБ · Web») и платформу.
2. Добавьте источники, одним из 2 способов:
   - **Текущий файл.** Откройте файл токенов, запустите плагин и нажмите «Добавить этот файл». Затем то же самое в файле ДС.
   - **По ссылке.** Если файл ДС только для просмотра: вставьте ссылку и личный токен Figma
     (Settings → Security → Personal access tokens, скоупы `file_content:read`, `file_variables:read`, `library_content:read`).
3. В «Исключениях» перечислите слои, которые специально отвязаны. Для ИБ это `Card`, `Детали платежа`, `Третье лицо`.

## Как проверять

Выделите один или несколько экранов на холсте → вкладка **Проверка** → «Проверить». В карточке «Что проверяем» видно превью, название и размер выделенного экрана. Целую страницу плагин не проверяет: на страницах с сотней экранов это слишком долго.
Клик по строке выделяет слой на холсте. «Исправить» привязывает слой к токену из профиля с тем же значением.
Кнопка появляется, только когда подходящий токен один; если вариантов несколько, плагин их покажет, но выбрать нужно вручную.

## Правила

| Правило | По умолчанию | Что ловит |
|---|---|---|
| Цвет без токена | ошибка | HEX в заливке или обводке |
| Градиент без стиля | предупреждение | градиент не из стилей библиотеки |
| Текст без стиля | ошибка | текст без текстового стиля |
| Отступ без переменной | предупреждение | padding / gap числом |
| Радиус без переменной | предупреждение | скругление числом |
| Эффект без стиля | предупреждение | тень или размытие вручную |
| Переменная из чужой библиотеки | ошибка | токен не из источников профиля — сверка по **ключу** коллекции, а не по имени |
| Стиль из чужой библиотеки | ошибка | стиль не из источников или локальный |
| Переменная не по назначению | предупреждение | скоуп переменной не разрешает свойство (отступ как радиус) |
| Устаревшая версия библиотеки | подсказка | переменной нет в последней синхронизации |
| Сломанный компонент | ошибка | главный компонент удалён из файла («Restore component»); плагин предлагает замену |
| Компонент не из ДС | ошибка | инстанс из библиотеки вне профиля |
| Локальный компонент | предупреждение | компонент создан в самом макете |
| Отвязанный компонент | предупреждение | detach от компонента |
| Нарушены настройки слота | предупреждение | слот: лишние элементы или неразрешённый компонент |
| Слой с именем по умолчанию | **выключено** | `Frame 2087330847`, `Group 3`, `Rectangle` у своих слоёв. Включается в профиле: Правила → Нейминг |

Уровень каждого правила меняется в профиле, любое правило можно выключить.

Нейминг выключен по умолчанию: в компонентах ДС много слоёв «Frame …», и на них правило ругалось бы постоянно.
Поэтому даже включённое правило смотрит только на свои слои и содержимое слотов, а слои внутри инстансов пропускает.
Чтобы разрешить конкретные имена, добавьте их в «Исключения».

## Автоисправления

Кнопка «Исправить» (у одного слоя, у группы или «Исправить» для всех) привязывает слой к токену или стилю ДС:

| Что | Как подбирается |
|---|---|
| Отступы и радиусы числом | переменная ДС с тем же значением; если такой нет — ближайшая, но не дальше 4 px (17 → `Space/4x` = 16, 10 → `Space/2x` = 8). Дальше 4 px — только подсказка |
| Переменная отступа/радиуса из чужой библиотеки | так же: своя переменная с тем же или ближайшим значением |
| Текст без стиля, с чужим стилем или чужими переменными шрифта | текстовый стиль ДС с той же насыщенностью и размером (Regular 14 → `Caption/Caption2`). Если точного нет — самый похожий: размер ±4 px, насыщенность до 2 ступеней (Inter Medium 15 → Open Sans SemiBold 14/16), с выбором из списка |
| Сломанный компонент | рабочий компонент с похожим именем — сначала в этом файле (все страницы), затем в библиотеках профиля; тот же вариант (Status=Default…). **Перед заменой плагин всегда спрашивает подтверждение.** Если ничего похожего нет — подсказка создать новый |
| Цвет HEX или из чужой библиотеки | цветовой токен с тем же значением, подходящий по скоупу |
| Чужой стиль — текстовый или цветовой | текстовый: самый похожий стиль ДС по размеру и насыщенности; цветовой: ближайший цветовой токен по назначению. Всегда 2–4 варианта на выбор, если точного совпадения нет |

Исправления к ближайшему значению помечены «ближайшее значение — проверьте вёрстку».
Сначала берутся переменные, у которых в скоупе явно указано нужное свойство (`Space/*` для отступов, `Radius/*` для радиусов,
`Border/*` для обводки, `Text/*` для текста). Переменные с «All scopes» (например `Font/Size/*`) используются, только если специальных нет.
Если подходят несколько токенов с одинаковым значением (`Background/Secondary` и `Background/Card`), в строке появляется список —
по умолчанию выбран первый, «Исправить» для группы применяет выбранные варианты.
Цвет без точного совпадения подбирается к ближайшему оттенку, если разница не больше 12 из 255 по каналу.

Подбор текстовых стилей использует параметры стилей из источника. Если профиль создан до этой версии,
обновите источник с токенами (кнопка ↻ в профиле) — плагин подскажет об этом в результатах проверки.

## Что проверяется внутри инстансов и слотов

- **Свои слои** (фреймы-обёртки, текст, фигуры) проверяются полностью.
- **Инстанс** проверяется на происхождение компонента. Внутри инстанса — только то, что дизайнер **переопределил**
  (overrides): значения, пришедшие из самого компонента ДС, не считаются ошибкой дизайнера. В отчёте помечено «в инстансе».
- **Содержимое слотов** проверяется как обычный макет — его кладёт дизайнер. В отчёте помечено «в слоте».

## Файлы

- `manifest.json`, `code.js`, `ui.html` — сам плагин, без сборки и зависимостей.
- `docs/preview.html` — превью интерфейса в браузере с тестовыми данными (`python3 -m http.server` в корне папки → `/docs/preview.html`).
- `docs/spacing-semantic-usage.md` — где в ИБ используется внешняя коллекция «Spacing semantic».
